# 2026-09-07 第二轮可靠性改进

本轮从第一轮已验收的 `3bf59230a9f75d6cc00341d97e4a7f4ee37a7083` 出发，在三个实现 worktree 和一个集成 worktree 中并行工作，并由独立审查者构造并发、崩溃及真实界面反例。

运行实现的最终提交为 `78b250d`；随后追加组合回归及大数据用例超时设置，整仓验收源版本为 `2dc8605`。下述桌面构建包含全部生产改动。

## 改动

- Goal 的决策、事件、投影与用量 receipt 在 SQLite `BEGIN IMMEDIATE` 事务中完成。独立连接与进程并发结算不会覆盖彼此；同一 turn 重试只记一次。暂停、清除后重建和替换沿用正确账本。所有生命周期写入及用量作用域捕获使用同一事务快照，包装器在提交后通知。
- 普通子任务在首次创建时同时持久化独立 token 与 generation 0 租约，覆盖排队和提交后通知等待；首次执行通过 CAS 转为 generation 1。过期恢复只处理有明确 admission 所有权的 pending 行，保留旧版无租约任务和团队待调度意图。中断、迟到回执和关闭失败都保持执行与恢复的所有权约束。
- Desktop 增加 `Jump to latest`：上翻阅读时保留位置，点击后恢复连续跟随，切换项目和任务后重置。内容折叠、输入框增高及异步历史恢复均会重新测量。真实窄窗口点击测试还发现并修复侧栏、工作台被零宽网格区域裁剪的问题。

## 独立反例

Goal 四个真实进程各结算 12 次，旧代码仅保留 12/48，新代码保留 48/48；同一 turn 四进程并发只产生一条 receipt。另覆盖数据库投影回滚、丢失确认后重试、异步事务回调拒绝，以及多层包装器通知。

子任务探针使用真实 SQLite 连接和自有进程，覆盖排队、创建提交后和启动提交后的进程终止。审查还构造了中断等待超过租约期限、逐次取时差异及跨 generation 的迟到成功回执，验证修复不能让已被回收的旧 runner 再次启动。

Desktop 使用本地 HTTP SSE 服务控制每次新增输出，经真实 provider、runtime 和 Electron 渲染链路验证跟随。测试通过普通点击打开侧栏、新建任务和切换工作台标签；没有用强制点击绕过布局问题。额外的 DOM 高度夹具只验证 ResizeObserver 行为，不代替流式链路。

组合验证覆盖 Observable 与 Printing 的两种嵌套顺序、单独禁用一项能力时另一项仍可执行，以及提交后每层各通知一次。四进程混合探针得到预期的 37 tokens、33 receipts 和 33 tasks；两类重复请求均仅落一次。

首轮整仓测试发现原有 256 万事件回放用例运行 5.12 秒，略超默认 5 秒超时，其他 2847 条通过。该用例检查保留数量和字节上限，没有 5 秒性能断言；单独重跑 15 条测试、1595 个断言在 3.28 秒内通过。为此只将这条大数据用例超时明确设为 15 秒，保留全部数据量及断言，再重跑整仓。

## 保证范围

跨进程 Goal 保证适用于参与事务入口的写入者；自定义非事务存储保留原有进程内队列。首次持久化前丢失的 usage、绕过事务直接构造事件的外部写入、崩溃后通知恰好一次均不在保证内。receipt 沿用事件历史，本轮没有新增 schema 或独立 receipt 表。

Admission 保证覆盖新建普通子任务；旧版无租约行和团队预声明调度意图不会被当作过期 admission 自动回收。进程探针只终止本次创建的进程，保留无关哨兵；测试使用 fake model 或本地 provider，不调用真实模型服务。
